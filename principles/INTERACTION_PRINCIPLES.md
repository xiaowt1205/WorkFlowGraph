# 互動層設計規範 — 畫布操作模式

適用範圍：`workflow-graph-app/public/index.html` 中的畫布互動層——滑鼠／鍵盤分派、
拖曳與框選、平移縮放、選取模型、右鍵選單。
**節點本身怎麼設計看 [`NODE_PRINCIPLES.md`](./NODE_PRINCIPLES.md)，這份管使用者怎麼操作畫布。**

修改互動行為前先讀完第 2 節（原則）與第 3 節（方法）；交付前對照第 6 節的 Checklist。

---

## 1. 現行操作模型

### 1.1 輸入分派優先序

`wrap` 的 `mousedown` 是唯一的入口，**由上往下逐層判斷，先命中先決定，不重疊**：

| 順序 | 條件 | 進入模式 |
|---|---|---|
| ① | 中鍵，或 `Space` ＋左鍵 | `pan`（平移） |
| ② | 命中 `#runpanel`（執行控制浮動窗） | 關選單後 return（面板自己的 handler 處理） |
| ③ | 非左鍵 | 直接 return（交給 `contextmenu`） |
| ④ | 命中 `.port` 且非執行中 | `wire`（拉線） |
| ⑤ | 命中 `.node` | `node`（選取＋拖曳，可整組） |
| ⑥ | 以上皆非（空白處） | `marquee`（框選） |

**浮動窗放在平移之後、其他一切之前**：面板是疊在畫布上的 UI，不該觸發框選或拉線；
但中鍵／`Space` 仍然要能從面板上開始平移（第 2.1 條的逃生路徑）。
`contextmenu` 與 `wheel` 也各自對 `#runpanel` 早退，面板上不會冒出節點清單、滾輪不會縮放畫布。

**平移放在最前面是刻意的**：不論游標下是節點、埠還是空白，中鍵／`Space` 一律平移。
使用者永遠有一個「不會誤觸任何東西」的移動手段。

### 1.2 手勢對照表

| 手勢 | 行為 |
|---|---|
| 中鍵拖曳 ／ `Space`＋左鍵拖曳 | 平移畫布 |
| 左鍵拖曳空白處 | 框選（`Shift` 為加選） |
| 左鍵拖曳節點 | 移動；該節點在選取集合內時整組移動 |
| 左鍵從埠拖曳 | 拉線；放開在空白處 → 開節點清單並自動接線 |
| 拖曳執行控制窗的標題列 | 移動該窗（雙擊標題列回右下角預設位置） |
| 空白處右鍵 | 節點清單（可搜尋） |
| 節點上右鍵 | 指令選單（重新命名／複製／斷開連線／刪除） |
| `Shift`＋點擊節點 | 加選／退選 |
| 滾輪 | 以游標為中心縮放 |
| `Del` / `Ctrl+D` / `Ctrl+A` / `Ctrl+Z` / `F2` | 刪除／複製／全選／復原／重新命名 |

### 1.3 拖曳狀態機

全域只有一個 `drag` 物件，`drag.mode` ∈ `pan` / `marquee` / `node` / `wire` / `panel`，
`mousemove` 與 `mouseup` 依 `mode` 分支。**同一時間只能有一種模式**，
`mouseup` 結束時一律 `drag = null`。

新增手勢時，是**多一個 mode 分支**，不是在既有分支裡塞條件。

### 1.4 選取模型與不變式

```
state.selection  // 檢查器的主對象：{kind:'node'|'edge', id} 或 null
state.selected   // 被選取的節點 id 集合（Set）
```

**不變式**：

- `selection.kind === 'node'` 時，`selected` 必須包含 `selection.id`
- `selection` 為 edge 或 null 時，`selected` 通常為空；例外是多選中（`selected.size > 1`
  而 `selection === null`），此時檢查器顯示「已選取 N 個節點」
- **任何選取異動都必須走 `setSelection()` 或 `setSelectedNodes()`**，不得直接指派
  `state.selection`。唯一例外是拖曳過程中的暫時高亮（只切 CSS class，不動狀態）

> 這條不是潔癖：改造前這兩者散落 12 處各自賦值，是多選功能最容易出現
> 「檢查器顯示 A、實際刪掉 B」這類錯誤的來源。

### 1.5 層級（z-index）

節點可以互相重疊，因此「誰在上面」必須是明確的規則，不能靠碰巧的 DOM 順序：

| 元素 | z-index | 說明 |
|---|---|---|
| `#edgesvg`（連線） | auto | 在節點之下 |
| `.node` | `1` | **必須有值**：有了它每顆節點才自成一個 stacking context |
| `.port` | `2` | 只在**所屬節點內**生效——埠在自己節點的卡片之上 |
| `.node.selected` | `3` | 選取中的節點浮到最上層 |
| `#marquee`（膠框） | `60` | 在所有節點之上 |
| `#runpanel`（執行控制窗） | `70` | 疊在畫布上的 UI：在膠框之上、選單之下 |
| `#ctxmenu` / `#nodemenu` | `120` / `121` | 最上層 |

**`.node` 的 `z-index:1` 不是裝飾。** 少了它，節點是 `z-index:auto` 的定位元素、不建立
stacking context，`.port` 的 `z-index:2` 會拿最近的 stacking context（`#viewport`）當基準，
於是**所有埠都浮到所有節點之上**：兩顆節點重疊時，後面那顆的埠會畫在前面那顆的卡片上，
而且該處按下去會變成從後面那顆拉線。

**選取即浮起**是使用者取回被壓住的埠的唯一手段（點一下該節點 → 它到最上層 → 埠可以拉）。
不要改成「用滑鼠 hover 浮起」（游標一移就跳層，會抖），也**不要靠重排 `state.nodes` 來換層級**
——那會改動圖的資料，害存檔被判定成有未儲存的變更（見 `NODE_PRINCIPLES.md` 第五節）。

### 1.6 選單

| 元素 | 用途 | 開啟方式 |
|---|---|---|
| `#ctxmenu` | 節點清單（搜尋、`↑↓`、`Enter`） | 空白處右鍵；或拉線放開在空白處（帶 `ctxWire`） |
| `#nodemenu` | 節點指令 | 節點上右鍵；`F2` 直接進重新命名 |

兩者互斥（開一個必關另一個），`Esc`、點擊選單外、畫布 `mousedown` 都會關閉。

## 2. 設計原則

### 2.1 永遠留一條逃生路徑

平移、`Esc`、點空白取消選取這類「脫離目前狀態」的操作，必須在**任何情境下**都有效，
不因游標位置或目前選取而失效。

### 2.2 一個手勢只有一個意義

同一組按鍵／按鈕在畫布上只對應一種行為。要新增行為就換一個手勢，
不要用「按住某鍵時左鍵的意思不同」以外的方式去多載（`Space`＋左鍵是明確的修飾鍵，可接受；
「短按是 A、長按是 B」不可接受）。

### 2.3 破壞性最小的預設

最容易誤觸的手勢（空白處左鍵拖曳）給**不會改變圖**的操作（框選），
會改變圖的操作放在更明確的手勢上（拖節點、拉線、選單指令）。

### 2.4 就近原則

右鍵選單開在游標處；新節點落在游標處；拉線產生的節點依資料流方向擺在游標的下游／上游側。
使用者的視線不必離開他正在看的位置。

### 2.5 一個使用者動作 = 一次復原

`pushHistory()` 以**使用者認知的一步**為單位，不是以程式碼的一次修改為單位。
「從埠拉線 → 選節點 → 自動接線」對使用者是一步，因此只 push 一次
（`addNode` 內已 push，後續 `connect()` 不再 push）。

拖曳類操作在**第一次真的移動時**才 push（`if (!drag.moved) pushHistory()`），
避免點一下沒動也塞一筆歷史。

### 2.6 不做無聲的事

- 接不上的節點型別**不列進清單**，而不是列出來卻默默不接線
- 不能執行的指令顯示為 disabled（如無連線時的「斷開所有連線」），而不是點了沒反應
- 需要使用者知道的狀態要看得見：框選膠框、選取邊框、選單標題的「已選取 N 個節點」

### 2.7 拖曳中不做整頁重繪

`mousemove` 期間只改必要的 `style` 與 `class`（`el.style.left`、`classList.toggle`），
**不呼叫 `renderAll()`**。狀態同步與檢查器更新留到 `mouseup`。
連線因為要跟著節點動，例外允許 `renderEdges()`。

### 2.8 鍵盤不搶輸入焦點

全域 `keydown` 一律先判斷 `ev.target` 是不是 `input,textarea,select,button` 或
`isContentEditable`，是就直接放行。`Space` 平移、`Del` 刪除、`Ctrl+A` 全選都套用這條——
否則使用者在檢查器打字會炸掉整張圖。

選單內的輸入框（搜尋、重新命名）要 `ev.stopPropagation()`，避免按鍵外洩到全域處理器。

### 2.9 擋掉瀏覽器的預設干擾

中鍵的自動捲動（`mousedown` 與 `auxclick` 都要 `preventDefault`）、
`Space` 的頁面捲動、畫布上的原生右鍵選單——這些都要主動擋，
但**只在畫布範圍內擋**，不要影響左側面板與右側檢查器的正常操作。

### 2.10 既有資料相容

互動改動不得改變圖的資料格式（節點欄位、埠名、edge 結構）。
若真的需要動，比照 `NODE_PRINCIPLES.md` 的相容性義務附上匯入遷移。

## 3. 修改方法

前端是**單一 90KB 檔案**，沒有建置流程也沒有模組邊界，因此改法本身要有紀律。

### 3.1 先讀，再定位

用 `grep -n` 找事件監聽與區塊註解（`/* ---------- xxx ---------- */`），
確認要改的程式碼邊界落在哪兩個註解之間，再動手。

### 3.2 錨點式修改，不整檔重寫

以「精準字串替換」修改：找到唯一錨點 → 替換；**找不到錨點就中止，不要模糊比對**。
整段替換時，起訖錨點都要是**相鄰的**區塊註解。

> ⚠️ 真實教訓：曾以「右鍵選單」為起點、「檢查器」為終點做整段替換，
> 中間其實還夾著「點選連線 / 縮放 / 鍵盤」三個區塊，差一點整段被吃掉。
> **替換前先確認起訖之間只有你要換的東西**（例如先列出區塊註解的行號順序）。

改動前先備份一份，改動後保留可還原的狀態。

### 3.3 語法檢查

抽出最長的 `<script>` 區塊丟 `node --check`，確認沒有語法錯誤再談行為。
這一步很便宜，每次改完都做。

### 3.4 行為驗證：用真實 DOM 測

互動邏輯不能靠讀程式碼確認，要**真的操作**。用 Playwright 對頁面跑：

- 開一個靜態伺服器指向 `public/`（後端 API 缺席不影響互動層）
- **測試開頭先清空預設載入的範例圖**，否則命中測試會被既有節點干擾
- 斷言用 `state`（`state.nodes` / `state.edges` / `state.selected` / `state.view`）
  搭配 DOM（`.node.selected` 數量、選單是否顯示），兩邊都要對

### 3.5 回歸清單（每次互動改動都要跑）

| 項目 | 判準 |
|---|---|
| 拉線 | 從輸出埠拖到輸入埠可建立連線，拖曳中有暫時線 |
| 點選連線 | 點連線可選取，`Del` 可刪除，且會清掉節點選取 |
| 縮放 | 滾輪以游標為中心，`state.view.s` 有變 |
| 平移 | 中鍵與 `Space`＋左鍵位移量 = 螢幕位移量，且**節點座標不變** |
| 節點拖曳 | 世界座標位移 = 螢幕位移 ÷ `view.s`；多選時各節點位移相同 |
| 復原 | `Ctrl+Z` 能一步還原剛才的使用者動作 |
| 左側面板 | 拖放與雙擊仍能新增節點 |
| 匯入匯出 | 匯出 JSON 再匯入，圖與行為一致 |

### 3.6 文件同步（依 `CLAUDE.md`）

- 操作方式有變 → 更新 `README.md` 的「畫布操作」表（**根目錄與 app 兩份鏡像都要改**）
- 一律在 `CHANGELOG.md` 當日區塊記一筆，並寫出「原本是什麼 → 改成什麼」
- 若引入新的原則或推翻既有原則 → 回頭更新這份文件

## 4. 常見陷阱

| 陷阱 | 症狀 | 處理 |
|---|---|---|
| 分派順序寫錯 | 在節點上按 `Space` 變成拖節點 | 平移判斷必須在埠／節點之前 |
| `mousemove` 呼叫 `renderAll()` | 拖曳卡頓、節點閃爍、事件目標消失 | 只改 style / class |
| `pushHistory()` 位置錯 | 一個動作要按兩次 `Ctrl+Z` | 一次使用者動作只 push 一次 |
| 先 `pushHistory()` 再 `pop()` 回滾 | 沒有實際改動的操作也會讓 `Ctrl+Y` 失效 | `pushHistory()` 會清空 `state.future`，`pop()` 救不回來；改成先 `snapshot()`、確定圖有變再 `pushHistory(before)` |
| `stopPropagation()` 順手擋掉關選單 | 選單開著時點連線／點某元素，選單關不掉 | 擋事件的分支要自己補上 `closeMenus()` |
| 全域 `keydown` 沒擋輸入框 | 在檢查器打字誤刪節點 | 先判斷 `ev.target` |
| 選單靠 `document` 點擊關閉 | 點選單自己也被關掉 | 判斷 `ev.target.closest('#選單')` |
| 中鍵未 `preventDefault` | 觸發瀏覽器自動捲動 | `mousedown` 與 `auxclick` 都要擋 |
| 選單開在畫面邊緣 | 選單被裁切 | 用 `getBoundingClientRect()` 夾住位置 |
| 子元素有 `z-index`、父容器沒有 | 節點重疊時，後面那顆的埠畫在前面那顆卡片上，該處按下變成拉線 | 父容器（`.node`）要自己建立 stacking context（`z-index:1`），子元素的層級才會被關在裡面 |
| Playwright 的 `mouse.click(x, y, {modifiers})` | 修飾鍵不生效，測試假性失敗 | 改用 `keyboard.down('Shift')` 包住點擊 |
| 疊在畫布上的浮動 UI 沒有早退 | 按面板變成框選、右鍵冒出節點清單、滾輪縮放畫布 | `mousedown` / `contextmenu` / `wheel` 都要 `closest('#面板')` 早退（`mousedown` 要放在平移分支**之後**） |
| 畫布上的按鈕按完仍留著焦點 | 接著按 `Space`（平移修飾鍵）等於再按一次那顆按鈕 | 點擊後 `blur()`（見 `#runpanel` 的 click handler） |
| 測試用 `display:none` 蓋掉總覽頁 | 快捷鍵全失效（`inOverview()` 看的是 `.show` class），Del／Ctrl+Z 假性失敗 | 測試要呼叫 `showEditor()` 進編輯器 |
| 測試沒清空範例圖 | 命中測試數量對不上 | 測試開頭重設 `state` |

## 6. 交付前 Checklist

- [ ] 新手勢在 `mousedown` 的分派順序中位置正確，且與既有手勢互斥
- [ ] 疊在畫布上的浮動 UI 有在 `mousedown` / `contextmenu` / `wheel` 三處早退，且不擋平移
- [ ] 新增的是獨立的 `drag.mode` 分支，`mouseup` 有把 `drag` 收乾淨
- [ ] 所有選取異動都走 `setSelection()` / `setSelectedNodes()`
- [ ] 會改變圖的操作都有 `pushHistory()`，且一個動作只有一次
- [ ] `mousemove` 期間沒有 `renderAll()`
- [ ] 全域鍵盤處理有排除 `input,textarea,select,button` 與可編輯區
- [ ] 需要擋的瀏覽器預設行為都擋了，且只在畫布範圍內
- [ ] 接不上／不能執行的選項不列出或 disabled，沒有無聲失敗
- [ ] `node --check` 通過
- [ ] Playwright 測過新行為，且第 3.5 節回歸清單全過
- [ ] README「畫布操作」表已更新（兩份鏡像）
- [ ] CHANGELOG 已記錄，並寫出「原本是什麼 → 改成什麼」
- [ ] 圖的資料格式沒有被動到（或已附匯入遷移）
