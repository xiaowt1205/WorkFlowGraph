# 節點總覽

WorkFlowGraph 內建的所有節點型別、用途，以及是否會呼叫 Claude（＝是否產生費用）。
節點的設計規範另見 [`principles/NODE_PRINCIPLES.md`](./principles/NODE_PRINCIPLES.md)。

| 節點 | 用途 | 經過 Claude？ |
|---|---|:---:|
| ⌨ 輸入 | 提供固定文字 | ❌ |
| 📄 外部檔案連結 | 讀本機檔案（md / txt / docx / xlsx / csv / html / json），Office 檔自動解出文字；路徑可用「📂 瀏覽」開系統檔案視窗選 | ❌ |
| 📁 資料夾連結 | 輸出**資料夾路徑字串本身**（用「📂 瀏覽」選），給程式碼查詢的 folder 埠、HTTP 請求等節點當參考值；**不讀取內容**——要讀檔案內容用「外部檔案連結」 | ❌ |
| ✍ Prompt 模板 | 組合多個上游輸入成一段文字；單一輸入埠可接多條線，模板內用 `@節點名稱` 引用（檢查器列出已連接節點，點一下插入） | ❌ |
| 🧠 LLM 呼叫 | 文字進、文字出；可選模型（haiku / sonnet / opus）與**輸出限制**（僅回答內容／僅程式碼／僅 JSON：守則注入＋強制後處理）；可設**會話名**（同名 AI 節點同一次執行依序共用一個 Claude 會話，材料以快取重用省 token）與**逾時上限** | ✅ |
| 𝑓 程式碼 | 執行你寫的 JavaScript（a、b、c 為輸入） | ❌ |
| ❯ Shell 指令 | 在**這台機器**上執行 shell 指令（cmd／bash／sh／powershell 可選、可設工作目錄與逾時）。輸出比照條件分支：結束碼 0 走「成功」埠（stdout）、非 0 走「失敗」埠（stderr）。**預設不能執行**，見下方〈Shell 指令節點的三道閘門〉 | ❌ |
| 🌐 HTTP 請求 | 呼叫任意 API | ❌ |
| 🤖 MCP 代理 | 把**節點指定的 MCP 伺服器**（HTTP 或 stdio，JSON 設定，可多台）的工具交給 Claude，讓它依任務自己決定呼叫哪些工具、幾次，回覆文字。邊界靠機制：`--tools ""` 關掉全部內建工具、`--strict-mcp-config` 只載入節點填的伺服器、`--allowedTools mcp__<名稱>`。**stdio 型伺服器會在這台機器啟動指令**，閘門比照 Shell 節點：模擬模式不呼叫、工具列「允許 Shell」、每份新設定首次執行先確認；HTTP 型不需要閘門。檢查器有「從 Claude Code 設定帶入」選單：列出本機 `~/.claude.json` 與各專案 `.mcp.json` 已設定的 MCP 伺服器，點選即複製成設定（存的是副本，圖不依賴本機設定）。可選模型、會話名、逾時。金鑰寫 `${環境變數名}`，不要寫明文 | ✅ |
| 🔍 網路查詢 | Claude 用 WebSearch 工具實際上網搜尋並整理（約 30 秒～2 分鐘）；**可選模型**——這通常是整張圖最貴也最慢的一顆，換小模型省最多 | ✅ |
| 🔬 程式碼查詢 | 對指定的**查詢起點資料夾**發問，Claude 以**唯讀工具**（Read / Grep / Glob，無 Bash、不能寫檔、不能上網）實際讀碼後回答。範圍語意：起點＝主要範圍與引用基準，**同一 repo 內的其他檔案也可唯讀查閱**（盤點「誰在用這個模組」需要它）。每條陳述附 `檔案:行號` 引用，**雙基準逐筆驗證**（起點內寫起點相對、起點外寫 repo 根相對；repo 之外一律判無效），無效引用與「完全沒有引用」都會寫進執行日誌。起點可填參數或接線到 `folder` 埠（接線優先）。可設**會話名**（同名節點共用會話：讀過的程式碼以快取重用，省最多；會話綁定起點）與**逾時上限**。可選模型，掃碼約 30 秒～數分鐘 | ✅ |
| ⑂ 條件分支 | JS 判斷式決定走 true / false 哪條路，未選中的分支整條自動跳過 | ❌ |
| ⇥ 合併 | 多條線接進單一埠；預設「全部串接」（可附來源標題），或「取第一個有值」 | ❌ |
| 💾 輸出檔案 | 產出檔案：md / docx / xlsx / txt / csv / html / json / 任意副檔名（檔名副檔名優先，同 Windows 慣例）；「參考樣板」埠接上樣板時，先由 Claude 依樣板重排內容再寫檔 | ⚠️ 接樣板時 |
| ⏏ 輸出 | 顯示最終結果 | ❌ |
| 📥 節點輸入 | **標記模組的輸入埠**：這張 FlowMap 被當作模組引用時，每個「節點輸入」就是模組節點左側的一個輸入埠（**埠名用內部節點 id，埠上顯示的是節點名稱**——改名不會斷線）。外面接了線就用外面的值；沒接線（或單獨執行整張 FlowMap）時用節點裡填的預設值 | ❌ |
| 📤 節點輸出 | **標記模組的輸出埠**：這個 FlowMap 被當作模組引用時，每個「節點輸出」就是模組節點右側的一個輸出埠。單獨執行時行為同「輸出」，把收到的值顯示出來方便測試 | ❌ |
| 🧩 FlowMap 模組 | 引用另一張 FlowMap（**同 Project 自動互通；跨 Project 需來源勾「🌐 公開」**），執行其**最後儲存的版本**；埠由來源的「📥 節點輸入／📤 節點輸出」明確決定——**沒有節點輸入就沒有輸入埠，輸出同理**（一般的輸入／輸出節點不會變成埠）。內部進度逐筆寫進執行日誌，AI 用量彙總顯示在模組節點上。循環引用會被偵測並擋下 | ⚠ 依內部節點 |
| ✎ 註解 | 畫布標註，不參與執行 | ❌ |

## Shell 指令節點的三道閘門

這是全 app 風險最高的節點：它在你的機器上執行任意指令，而工作流是**可匯出、可分享、可匯入**的
內容。因此能力邊界用機制擋，不靠提醒：

1. **模擬模式下根本不呼叫後端**，回一段假輸出。想試接線不必擔心誤觸。
2. **工具列的「允許 Shell」總開關，預設關閉，而且不會被記住**——每次重新整理都回到關閉。
   開關關著時節點直接報錯（不是無聲跳過）。匯入別人的工作流不可能默默執行任何東西。
3. **每一段「新的指令內容」第一次執行時會跳確認對話框**，把完整指令、shell 與工作目錄攤開給你看。
   核准只在這次開頁期間有效，而且指令、shell、工作目錄任一改變就會重新詢問。
   核准紀錄**不會寫進存檔**（否則匯出給別人就變成預先核准）。

另外兩件設計上的決定：

- **指令只能在節點裡手打，沒有「指令」輸入埠。** 上游的值透過 **stdin** 與環境變數
  **`WFG_IN`** 送進去（值超過 8KB 時只走 stdin，並在日誌講明）。命令列的形狀完全由工作流的
  作者決定，上游資料再怪也只是資料——不做字串拼接，就沒有注入面。
  用法示例：`read line; echo "收到 $line"`、`grep -c TODO <<< "$WFG_IN"`。
- **伺服器只聽 127.0.0.1。** 有了這個端點，綁 `0.0.0.0` 等於把「在我機器上跑指令」開放給
  同網段的任何人。真要對外請自己設 `HOST=0.0.0.0` 並自負風險。

「跑不起來」（開關關著／使用者取消／逾時／找不到 shell／工作目錄不存在）算**節點錯誤**，
不是「失敗」分支；「失敗」分支只給「指令真的跑完但結束碼非 0」。逾時會殺掉整棵行程樹，
不會留下孤兒行程。stdout／stderr 各最多留 1MB，超過會截斷並在日誌講明。

## 費用與用量

費用只發生在 ✅ / ⚠️ 觸發時。模擬模式下所有節點都不呼叫 Claude，也不會有任何用量。

### 想省錢先看這兩件事

1. **模型**：這是最大的變數。工具列的「預設模型」一次設定所有 AI 節點，個別節點可以再覆蓋。
   只需要回一個詞的分類節點用 `haiku` 與用 `opus`，實測差了兩個量級；`sonnet` 通常是
   網路查詢與摘要類節點的甜蜜點，最終要給人看的回覆才留給 `opus`。
2. **快取**：每次呼叫都會帶上 Claude Code 自己的系統提示（約 2 萬多個 token），
   這是輸入端的大宗。**同一組 System 提示第一次用要付一次「快取建立」，一小時內再用就是
   便宜很多的「快取讀取」**。所以：System 提示寫定就別一直微調文字，同一張圖重跑第二次會明顯便宜。
3. **會話**：多顆 AI 節點要用到**同一批材料或同一份程式碼**時，填相同的「會話名」——
   後面的節點會延續前面的 Claude 會話，已讀入的內容以快取計價重用，不必每顆重讀重餵。
   會話表屬於「單次執行」（跑完即棄、不跨執行）；程式碼查詢的會話綁定根目錄，同名不同根目錄不共用。
   **需要獨立判斷的節點（驗證、拷問、對抗性審查）請留空**——隔離在那裡是功能，不是成本。

### 逾時怎麼判定（不會誤殺大工作量）

AI 節點的逾時是**活動式**的：只要子行程持續有輸出（工具呼叫、生成中的文字），就不會被砍；
連續 3 分鐘（`WFG_IDLE_MS` 可調）完全沒有輸出活動才視為卡死。另有硬上限
（LLM／網路查詢預設 900s、程式碼查詢預設 1800s，節點的「逾時上限」參數可調）。
執行日誌每 15 秒回報一行進度（`工具呼叫 N 次｜已產生 X 字`），慢節點是活是死一眼可辨。

執行中的節點會在標題右側**即時讀秒**（`執行中 12.3s`，超過一分鐘改成 `1:23`），
所以慢的節點——特別是動輒 30 秒起跳的網路查詢——一眼就知道是還在跑還是卡住了。

真實模式下，**每個經過 Claude 的節點執行完會直接在節點上顯示這一步的用量**：

```
↑ 8.1k ↓ 380 tok · $0.0042 · 3.1s
```

- **↑ 輸入 / ↓ 輸出**：這次呼叫的 token 數（輸入已含快取讀取與快取建立）
- 點選該節點，右側檢查器會展開明細：新送出、快取讀取、快取建立、輸出、費用、耗時
- 工具列右上與執行日誌結尾會顯示**本次執行的總計**；按「↩ 重製」或重新執行即歸零
- 一個節點若觸發多次呼叫（例如輸出檔案節點接了樣板），數字為該節點的累計，並標示呼叫次數

> 數字來自本機 `claude` CLI 回報的 `usage` 與 `total_cost_usd`。使用 Claude 訂閱時，
> 金額是「若以 API 計價的等值成本」參考值，不是實際帳單；token 數則是實際用量。
> 舊版 CLI 若沒回報 `usage`，token 數會顯示 0，只有費用與耗時可參考；
> 若連費用也沒回報，就完全不顯示用量列。
